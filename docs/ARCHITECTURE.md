# 技术设计

## 选型

选择原生 ES modules、DOM 与 SVG。25 格回合制棋盘不需要持续物理模拟，也不需要下载大型引擎；静态文件可通过 GitHub Pages 分享。开发和游玩不调用模型或付费后台。

Phaser 更适合需要大量精灵、摄像机和碰撞的浏览器动作游戏；Godot 更适合依赖编辑器、场景组合或原生导出的项目。若加入实时飞船物理或大量动态实体，再评估迁移；当前优先保留简单、可读和可复现的规则。

## 状态与模块

- `levels.js`：关卡、方向位掩码、参考解与初始旋转。每个格子的四个方向使用 1 / 2 / 4 / 8 表示。
- `rules.js`：连通遍历、旋转、撤销、提示和输赢。相邻格子必须同时有互相对应的开口，边界不能跨行连接。
- `storage.js`：版本化记录、字段筛选、200 条事件上限以及读写异常回退。
- `app.js`：输入、可访问 DOM、声音、对话框、分享与记录导出。展示不能自行判胜或修改规则。

棋盘改变后从能源端做广度遍历。判胜优先于次数用尽；历史快照用于恢复棋盘和次数。提示遵循已知可恢复的参考解，只标记下一块应调整的线路，不自动通关。

## 数据与资源

记录保存在当前浏览器，包含关卡、动作、次数、时间和固定选项反馈；仅用户导出文件或主动分享链接时离开浏览器。不采集身份信息，不连接远程分析服务。

SVG 和 CSS 绘制线路及背景；短提示音使用 Web Audio，在主动操作后创建。所有模块路径相对当前页面，适配 GitHub Pages 仓库子目录。声音不可用时保留视觉反馈，不阻断游戏。
